# Использование

```
rustsheng [OPTIONS] <COMMAND>
```

Выполните `rustsheng --help` или `rustsheng <команда> --help` для встроенной справки.

## Глобальные опции

| Опция | Описание |
|--------|-------------|
| `-v, --verbose` | Повысить детализацию (можно повторять): `-v` = info, `-vv` = debug, `-vvv` = trace (hex tx/rx). |
| `-h, --help` | Вывести справку. |
| `-V, --version` | Вывести название, версию и автора. |

Подкоманды радиостанции требуют подключения:

| Опция | Описание |
|--------|-------------|
| `-p, --port <PORT>` | Последовательный порт, например `/dev/ttyUSB0` или `COM3`. |
| `-s, --speed <BAUD>` | Скорость порта; по умолчанию **38400** (скорость UV-K5). |

Переведите радиостанцию в **обычный режим** (включение *без* PTT) для
EEPROM/калибровки/ADC/RSSI/сброса. Переведите в **режим прошивки** (включение
*с удержанием PTT*) для `bootloader-info` и `flash`.

## Команды

### `scan-ports`
Выводит список последовательных портов, известных ОС. Без взаимодействия с
радиостанцией.
```bash
rustsheng scan-ports
```

### `read-eeprom` (псевдоним `r`)
Читает EEPROM в файл. По умолчанию полный образ, либо диапазон через
`--offset`/`--size` (десятичные или `0x` hex; адресуемый диапазон до `0x10000`).
```bash
rustsheng read-eeprom -p /dev/ttyUSB0 -o backup.raw
rustsheng read-eeprom -p /dev/ttyUSB0 --offset 0x1e00 --size 0x200 -o calib.raw
```

### `write-eeprom` (псевдоним `w`)
Записывает EEPROM из файла. Полнообразный режим требует ровно `0x2000` байт и
принимает `--mode`:

| Режим | Записывает |
|------|--------|
| `original` (по умолчанию) | заводской набор/порядок блоков (самый безопасный) |
| `most` | всё до `0x1d00` (без калибровки) — подтверждение не требуется |
| `all` | весь EEPROM, включая калибровку — требует `--i-know-what-im-doing` |

Частичная запись размещает файл по произвольному `--offset` (продвинутый режим;
требует `--i-know-what-im-doing`):
```bash
rustsheng write-eeprom -p /dev/ttyUSB0 -i backup.raw --mode original
rustsheng write-eeprom -p /dev/ttyUSB0 -i patch.bin --offset 0x0e70 --i-know-what-im-doing
```

### `read-calibration` / `write-calibration`
Чтение/запись калибровочной области `0x1e00..0x2000` (`0x200` байт). Запись
калибровки требует `--i-know-what-im-doing`.
```bash
rustsheng read-calibration -p /dev/ttyUSB0 -o calib.raw
```

### `reset`
Перезагружает радиостанцию.

### `read-adc` / `read-rssi`
Чтение АЦП батареи или RSSI/шум/glitch. Зависит от прошивки (может завершаться
по таймауту на кастомной прошивке).

### `bootloader-info`
Ожидает beacon-пакет в режиме прошивки и выводит версию бутлоадера и
определённый протокол (V2/V5). Требует радиостанцию в режиме прошивки.

### `flash` (псевдоним `F`) — **опасно, не проверено на оборудовании**
Прошивает образ микропрограммы (сырой или vendor-зашифрованный `.bin`,
автоопределение). Протокол бутлоадера (V2 или V5) выбирается по beacon.

| Опция | Описание |
|--------|-------------|
| `-i, --input <FILE>` | Образ прошивки. |
| `-M, --fw-version <VER>` | Строка версии, отправляемая бутлоадеру (по умолчанию `*.01.23`). |
| `--key-number <0..15>` | Пара ключей AES для V5 (по умолчанию 0). |
| `--dry-run` | Собрать поток пакетов и записать в файл **без открытия порта**. |
| `--protocol v2\|v5` | Протокол для `--dry-run` (в реальном режиме автоопределяется). |
| `-o, --output <FILE>` | Выходной файл для `--dry-run` (по умолчанию `<input>.packets.bin`). |
| `--i-know-what-im-doing` | Повторяемое подтверждение. Для реального V2 нужно ≥3, для V5 — ≥5. |

```bash
# Безопасный офлайн-просмотр пакетов (без радиостанции, без подтверждения):
rustsheng flash -i firmware.bin --dry-run -o packets.bin

# Реальная прошивка (радиостанция в режиме прошивки) — ТРЕБУЕТ подтверждения:
rustsheng flash -p /dev/ttyUSB0 -i firmware.bin \
    --i-know-what-im-doing --i-know-what-im-doing --i-know-what-im-doing
```

### `unpack` / `pack` — офлайн-инструменты для прошивки
`unpack` расшифровывает vendor-упакованный образ в сырой; `pack` собирает vendor-образ
(вставляет 16-байтную версию по `0x2000`, XOR-обфусцирует, добавляет CRC). Без
радиостанции.
```bash
rustsheng unpack -i vendor.bin -o firmware.raw
rustsheng pack   -i firmware.raw -M "2.01.23" -o vendor.bin
```

### `parse` — офлайн-декодер датаграмм
Декодирует hex-датаграмму и выводит название пакета.
```bash
rustsheng parse "ab cd 08 00 02 69 10 e6 44 a8 5a 24 b9 a9 dc ba"
# Payload (8 bytes): 14 05 04 00 6a 39 57 64
# Packet: HelloReq (0x0514)
```

### `sniffer`
Пассивно читает порт, извлекает датаграммы из потока и выводит их декодированное
представление до нажатия Ctrl-C. Полезен в режиме прошивки, где бутлоадер
транслирует beacon.
```bash
rustsheng sniffer -p /dev/ttyUSB0
```

## Защитные ограничения

Опасные операции отказываются выполняться без повторяемого
`--i-know-what-im-doing` (аналог `-Y` в оригинальном `k5prog`):

| Операция | Требуемый уровень |
|-----------|----------------|
| `write-eeprom --mode all` | ≥ 1 |
| `write-eeprom --offset` (частичная) | ≥ 1 |
| `write-calibration` | ≥ 1 |
| `flash` (V2) | ≥ 3 |
| `flash` (V5) | ≥ 5 |
| `flash` подозрительно маленького образа | ≥ уровень + 2 |

## Устранение проблем

- **Нет `/dev/ttyUSB*`:** проверьте кабель/драйвер; `scan-ports` покажет, что
  видит ОС.
- **Permission denied на Linux:** добавьте себя в группу `dialout`
  (`sudo usermod -aG dialout $USER`, затем перезайдите).
- **Таймаут `read-adc`/`read-rssi`:** прошивка не реализует эти
  последовательные команды (обычное дело на кастомных прошивках).
- **Ничего не декодируется / плохой CRC:** попробуйте `-vvv` для просмотра
  сырых tx/rx; проверьте порт и скорость 38400.
